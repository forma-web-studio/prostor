# Разработка ПРОСТОР через обычный Chat и Codex

> Архивный ручной сценарий. Для текущей реализации от 08.09.2026 использовать [IMPLEMENTATION_HANDOFF.md](IMPLEMENTATION_HANDOFF.md): два ограниченных этапа Terra с контролем Astra между ними. Инструкции ниже не расширяют текущий этап.

## Постоянный контекст для Chat

В начале отдельного чата приложи README.md, ARCHITECTURE.md, VISUAL.md этого проекта и картинку из references. Затем вставь:

> Мы разрабатываем ПРОСТОР, учебный сайт для портфолио. Следуй приложенным документам. Стек Astro + TypeScript + CSS. Архитектура и дизайн-токены уже выбраны. Делай только текущий этап. Перед изменением существующего компонента опирайся на его актуальный код, а не на предполагаемую версию. Возвращай список изменённых путей и полное содержимое каждого изменённого файла без сокращений, затем краткие шаги проверки. Не меняй контракты и зависимости незаметно. Не добавляй сервер, CMS, оплату, несуществующие отзывы или фиктивную отправку формы. Если для шага не хватает актуального файла, сначала перечисли нужные файлы.

Обычный Chat не следует считать автоматически подключённым к локальной папке: необходимые документы и актуальный код передавай ему вручную. Этапы ниже отправлять по одному, после запуска предыдущего результата. Если ответ становится слишком большим, раздели этап по компонентам, сохранив их интерфейсы.

## 1. Каркас в Codex

Создай запускаемый каркас Astro + TypeScript со статической сборкой, проверкой типов и base-aware ссылками. Реализуй BaseLayout, Header с мобильным меню, Footer, Button, tokens.css и global.css. Подготовь тип Project и данные четырёх вымышленных проектов по README. Пока не создавай все страницы; главная может содержать только hero. Не добавляй новые библиотеки без необходимости.

## 2. Первый экран в Chat

Реализуй hero главной ПРОСТОРА по VISUAL.md: крупный serif-заголовок, короткое описание, две ссылки и архитектурная фотография. Учитывай 360/390/768/1440 px. Если файл фотографии ещё не подготовлен, назови точный требуемый путь и размер; не выдавай отсутствующий ресурс за готовый.

## 3. Главная в Chat

Добавь избранные проекты, манифест, процесс и финальный CTA. Используй ProjectCard и данные projects.ts, не дублируй контент. Сохрани header, hero и общие токены.

## 4. Кейс в Chat

Реализуй статический маршрут /projects/[slug]/ через getStaticPaths и шаблон кейса Свет и дуб: факты, задача, решение, галерея, материалы, следующий проект и CTA. Остальные кейсы должны собираться тем же шаблоном.

## 5. Каталог и страницы в Chat

Реализуй /projects/ с доступным фильтром и query type, /studio/ и /contact/ с честной демоформой. Добавь 404. Соблюдай без-JS поведение и состояния ошибок из ARCHITECTURE.md.

## 6. Контроль в Codex

Запусти проверку типов и production build, проверь ссылки и страницы на 390 и 1440 px в браузере. Проверь фильтр, мобильное меню и демоформу. Сравни с референсом и VISUAL.md. Исправь обнаруженные дефекты точечно, сохрани дизайн. Укажи, какие проверки фактически выполнены и какие не удалось выполнить.

## Контрольные точки

После каркаса должны работать команды разработки, проверки типов и сборки (точные команды фиксируются в package.json при реализации). После hero — визуальная проверка телефона и desktop. После первой внутренней страницы — проверка повторного использования компонентов. Финальная сборка — только после добавления всех изображений и проверки каждого URL.

Если ошибка: передай точный текст ошибки, путь файла и актуальный код связанных компонентов. Проси минимальное исправление. Если визуал не устраивает: приложи снимок текущей страницы и назови конкретное расхождение — размер заголовка, поля, кроп фото, контраст, порядок секций.
